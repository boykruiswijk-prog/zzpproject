# Beheer-UI
- Lead status menus use shared type-specific options; historical current statuses are visible but disabled. Status edits preserve linkage and converted_at; closed rows are opt-in or shown under Alle, never lead work items. Why: closing a question must not unlink a customer or change policy state.

- Aantallen (klanten, contracten, service open, aanvragen doel) alleen via SQL tel_* functies, gedeeld door dashboard_tellers, mijn_acties_vandaag, scherm_data en scherm_stromen; nooit getallen uit marketing_snapshot-tekst. Waarom: dashboard en tv tonen altijd hetzelfde.
- Admin onder lg: Sheet-menu en kaartlijsten; desktop vaste zijbalk. Waarom: één navigatie.
- Universal admin search uses only zoek_universeel with explicit aal2 and existing insurance/supervisor/admin roles; allowlisted source view is not browser-readable, IBAN is masked and audited even for zero matches, merged-card aliases resolve to the main card. Why: exhaustive prospect/customer discovery without exposing raw bank data or bypassing permissions.
- KVK: elke bevraging via haalKvkProfiel in _shared/kvk.ts (formaat, cache kvk_profielen 30 dagen, schakelaar integratie_config 'kvk_api', limieten kvk_instellingen, claim per nummer, alleen Basisprofiel, log kvk_opvraag_log met kosten_eur); alleen na echte aanvraag of teamknop, nooit vanuit het openbare formulier; KVK-oordeel startertarief is een voorstel; KVK-waarden apart in ondernemingen.kvk_*, eigen naam/adres alleen via kvk_gegevens_overnemen. Waarom: geen onnodige kosten, misbruik of ongevraagd overschrijven.

- Serviceaanvragen bijwerken alleen via RPC service_aanvraag_status/afronden/notitie (src/lib/serviceAanvraag.ts), fout bij 0 rijen. Waarom: geen stille RLS-weigering.
- Teamrollen hebben geen SELECT op IBAN-kolommen: nooit select("*") op leads/ondernemingen/screening_aanvragen e.d. (kolomlijsten in src/lib/veiligeKolommen.ts), masker/geldigheid via RPC iban_maskers, mandaten via klant_mandaat_overzicht, volledig IBAN alleen via iban_inzien (IbanInzien, gelogd). Nieuwe kolom op die tabellen krijgt een expliciete kolom-GRANT. Waarom: inzage herleidbaar, geen ruwe bankgegevens in de browser.
- Leadvlag (later/actie) alleen via RPC zet_lead_vlag/verwijder_lead_vlag (trigger guard_lead_vlag); "geparkeerd" = SQL lead_vlag_geparkeerd, byte-gelijk aan isGeparkeerd in src/lib/leadVlag.ts. Waarom: tabs, tellers en dagoverzicht hanteren één regel.
- Contractkorting: bedrag_per_periode blijft bruto; korting alleen via RPC zet_contract_korting/verwijder_contract_korting (guard_contract_korting), netto via SQL korting_netto/korting_voor_periode in facturatie_kandidaten, gespiegeld in src/lib/contractKorting.ts; Exact-regel UnitPrice netto zonder Discount-veld. Waarom: nooit terugwerkend, creditnota's rekenen met het betaalde bedrag.
- Klantvlag (ondernemingen) alleen via RPC zet_klant_vlag/verwijder_klant_vlag (trigger guard_klant_vlag, log klant_vlag_log); zelfde geparkeerd-regel als leadVlag (filterOpTab/isGeparkeerd). Waarom: leads en klanten hanteren één vlagregel.
- Inzicht-detailpagina's (/admin/inzicht/:tegel) halen de stand alleen via RPC inzicht_tegel, die dashboard_tellers/arr_overzicht/mijn_acties_vandaag aanroept; historie uit bestaande data of admin_teller_historie (cron admin-teller-momentopname, 23:55 NL). Waarom: detail en dashboard tonen altijd hetzelfde getal.
- Admin chart drill-down: chart counts come from RPC admin_grafiek and the side-panel list from admin_grafiek_records, both over the single internal source admin_grafiek_bron (NL time zone, is_test excluded, aal2 + admin/supervisor/verzekering; ARR supervisor/admin only); never read tables directly for charts. Why: list length always equals the clicked value.
- Mijn ZP gegevens alleen via RPC mijn_gegevens_* (eigen persoon, lege velden, telefoon_normaliseer = normaliseerTelefoon); afhakerregels in src/lib/afhakers.ts gelijk aan SQL. Waarom: eigen gegevens, teller = echt werk.
- Admin discovery uses the allowlisted admin_zoek_bronnen view behind the MFA-only zoek_universeel RPC; unlinked records open a read-only search-backed detail page, never arbitrary table fetches. Why: full discovery without exposing raw records.
- Application tabs exclude active policies only from the application To do view; SQL action counters exclude them from application work while retaining real policy-management actions. Why: archive access and shared admin/screen counts without status changes.

## CRM (verplaatst uit crm/AGENTS.md)
- Dubbele klantkaarten alleen samenvoegen via RPC onderneming_samenvoegen (supervisor/admin/verzekering, 2FA; zet samengevoegd_naar, verplaatst alle koppelingen, verwijdert niets, audit plus CRM-notitie); overzicht via RPC dubbele_klanten op /admin/dubbele-klanten. Nieuwe kaarten: trigger weiger_dubbele_kvk weigert een tweede echte niet-samengevoegde kaart met hetzelfde KvK; activatie (kiesKaartOpKvk) en koppel_bronrecord_aan_persoon hergebruiken de bestaande kaart. Waarom: een KvK hoort op een kaart.
- Persoon met meerdere ondernemingen: koppelen/ontkoppelen alleen via RPC persoon_onderneming_koppelen/_ontkoppelen (aal2, audit + notitie; ontkoppelen haalt Mijn ZP-toegang tot die polissen weg); Mijn ZP groepeert via mijn_ondernemingen/mijn_klant_contracten_per_onderneming. Waarom: eenmanszaak en BV onder één login zonder andermans polissen.
- Omzetting eenmanszaak naar BV: polis gaat met hetzelfde BAV-nummer naar de opvolger alleen via generate-certificate actie omzetten (RPC polis_omzetten -> service-only polis_omzetten_kern: policy_versies 'omgezet' met oude PDF, onderneming_opvolging, personen mee, audit, nooit mail, contracten ongewijzigd); Ondernemingswijziging met soort rechtsvormwijziging en _polis_meenemen gebruikt na bevestiging dezelfde route; een open opvolging (polis nog bij voorganger) toont op de opvolger geen BAV-nummer maar 'Polis overnemen' (src/lib/omzetting.ts openOmzetting); eenmalige uitvoering zonder teamsessie alleen via omzetting_systeem_opdrachten-token. Waarom: één route en het scherm toont niets wat de data niet heeft.
- Aanvraag afgerond alleen via leads.aanvraag_afgerond_op (trigger bij certificaatmail of RPC aanvraag_handmatig_afronden met reden); stappen via RPC aanvraag_stappen. Waarom: niets valt uit Te doen voordat het certificaat verstuurd is.
- Rechtsvormwijziging zonder eigen BAV + AVB-contract bij de opvolger: het contract gaat mee via service-only contract_meenemen_kern (aangeroepen door crm_ondernemingswijziging of RPC contract_meenemen, aal2): onderneming_id naar opvolger, beeindiging door de wijziging ongedaan, gefactureerd_tm/volgende_factuurdatum ongewijzigd, nooit creditnota, BAV-nummer op onderneming_opvolging, taak 'opvolger_exact_machtiging' voor Exact-relatie en machtiging; generate-certificate maakt van een overgenomen nummer versie 2. Waarom: geen dubbele factuur en de planner factureert de opvolger pas na eigen Exact-koppeling.
- Rechtsvormwijziging datums (besluit 12-11-2026 12:11): einde oud en start nieuw mogen overlappen of een gat hebben (datumsMelding waarschuwt, blokkeert niet); oude contracten stoppen exact op de opgegeven einddatum via crm_ondernemingswijziging(_einddatum); geen automatische credit voor overlap. Waarom: de overeenkomst met de opdrachtgever bepaalt de periode.
- Rechtsvormwijziging standaardroute (besluit 12-11-2026): klant zegt op en vraagt nieuw aan; team koppelt via RPC onderneming_koppel_vorige (aal2, reden 10-500, audit + notitie op beide) in onderneming_koppelingen, nooit onderneming_opvolging (die verplaatst BAV-nummers). Aanvraagveld via src/lib/vorigeOnderneming.ts in extra_data.formulier. Omzetten blijft, staat standaard uit. Waarom: koppeling zonder polis-, nummer- of bankeffect.
- Zelfservice rechtsvormwijziging: Mijn ZP /portal/rechtsvorm -> Edge Function klant-rechtsvormwijziging (eigen geldige polis, regels in _shared/rechtsvormwijziging.ts, machtiging via legBewijsVast, geen mail) maakt klant_service_aanvragen type rechtsvormwijziging; team keurt goed via RPC rechtsvormwijziging_goedkeuren (aal2, hergebruikt crm_ondernemingswijziging + koppeling), daarna generate-certificate omzetten en rechtsvormwijziging_afronden. Waarom: bestaande omzet- en factuurroute, geen nieuwe facturatielogica.
- Ingangsdatum van een contract wijzigen alleen via RPC contract_wijzig_ingangsdatum (aal2, blokkades in contract_ingangsdatum_blokkade, gespiegeld in src/lib/ingangsdatumWijzigen.ts; polissen via contract_polissen_bij_ingang, zelfde koppeling als crm_dossier), daarna generate-certificate aanpassen zonder mail; mailen alleen via aparte klik. Waarom: alleen zolang er niets gefactureerd is, nooit Exact.
- Admin tab titles only via src/lib/adminTitels.ts (route table, reset on route change, name only when data id equals URL id); admin pages set no Helmet title. Why: never show a previous customer.
