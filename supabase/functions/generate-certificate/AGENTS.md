# Afspraken certificaten
- Certificaten per klant staan in klant_certificaten, uniek op onderneming+nummer+aanvraagdatum; import via importeer_certificaten_20261001 (idempotent, service_role), voorstellen via RPC beoordeel_klant_certificaat; generate_certificate_number kiest bij leeg nummer via certificaatnummer_voorstel(_intern) het bekende klantnummer (overgenomen, bevestigd, klant_certificaten bevestigd, eerdere policy; onderneming anders via lead) en geeft alleen bij "NIEUW" of geen bekend nummer een vrij nummer uit, nooit een nummer van een geldige policy van een andere klant. Waarom: nummer alleen is geen sleutel.
- Certificaatnummer onveranderbaar; nieuw/aanpassen/intrekken/mailen via generate-certificate (supervisor/admin), versies in policy_versies, ingetrokken telt niet mee; klant zonder lead via policies.onderneming_id met eigen klant_certificaten-nummer (regels in _shared/certificaatRegels.ts). Waarom: altijd spoor, nooit andermans nummer.
- D7: certificaat pas vanaf ingangsdatum min 1 kalendermaand (_shared/certificaatBeschikbaar.ts byte-gelijk src/lib; generate-certificate 409 certificaat_te_vroeg; storage-policy klant idem). Ingang na vandaag: activatie maakt geen Exact-factuur maar zet contract via zetInPlanner(opIngang) zodat factuur-planner op de ingangsdatum factureert. Waarom: niets afgeven of factureren voor de polis begint.
- Certificate previews run the production PDF drawing block locally with fictitious fields, never the privileged handler. Why: identical rendering, no customer effects.
- Cybercertificaat is een aparte PDF via generate-cyber-certificate (supervisor/admin met MFA, nooit mailen of overschrijven); teksten in _shared/cyberCertificaatTeksten.ts, tekenen in _shared/cyberCertificaatPdf.ts; BAV-certificaat blijft los. Waarom: cyber eigen document zonder BAV-wijziging.
- Certificaatnummer bij omzetting: trigger generate_certificate_number gebruikt het via omzetting_vastleggen overgenomen BAV-nummer (overgenomen_certificaatnummer); bij een open omzettingsvoorstel weigeren lead-to-exact-activate en generate-certificate ("Beslis eerst over de omzetting"); na activatie vervangt alleen RPC policy_nummer_overnemen (via generate-certificate actie nummer_overnemen, nieuwe PDF, oud nummer als policy_versies 'nummer_vervangen', nooit mail) het nummer. Waarom: een opvolger houdt het BAV-nummer van de voorganger.
- Certificaatnummer nooit ongezien (A14): trigger generate_certificate_number weigert een leeg nummer zonder bekend voorstel; nieuw nummer alleen via 'NIEUW' na bevestiging in de dialoog (voorbeeld via RPC volgend_vrij_certificaatnummer_voorbeeld, verbruikt niets); zelf getypt nummer eerst via bav_nummer_handmatig_bevestigen; nummer op bestaand certificaat alleen via RPC policy_nummer_wijzigen (generate-certificate actie nummer_wijzigen, reden >= 10, bezet alleen na override, nooit mail). Waarom: het team ziet en bevestigt elk nummer.
- Policies get onderneming_id on insert via trigger aa_policy_onderneming_afleiden (policy_onderneming_afleiden: strong route lead link/Exact code/KvK, else all routes unique); certificaatnummer_voorstel searches onderneming plus its leads (onderneming_lead_ids); NIEUW is refused when bestaand_geldig_bav_nummer finds a valid BAV number (onderneming, lead or same KvK). Why: never a second number for an existing customer.
