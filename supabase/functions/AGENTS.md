# Afspraken facturatie, Exact en certificaten
- Lopende contracten staan in klant_contracten via exact_relatie_code; importeer_afas_20261001 is idempotent en alleen service_role.
- Facturatiegrens: administratie t/m 12-10-2026, platform vanaf 13-10-2026 (doorrol_startstand, PORTAL_FACTUREN_VANAF, creditteksten); herstelde startstand heeft bron doorrol_20261012 met audit doorrol_herstel_20261012. Waarom: geen periode dubbel of overgeslagen.
- Startertarief: regels in src/lib/starterTarief.ts (byte-gelijk _shared/starterTarief.ts); server bepaalt starter, activatie wacht op RPC beoordeel_startertarief (verzekering, supervisor of admin); activatie herstelt een ontbrekende bav_aanmeldingen-rij alleen additief vanuit de lead; planner rekent per periode via contract_bedrag_voor_periode (tarief_type/starter_tot/bedrag_na_starter). Waarom: geen Exact-inrichting en geen verkeerd bedrag.
- Kennisbank-IndexNow: trigger trg_indexnow_artikel zet URL's in indexnow_log en wekt indexnow-ping {wachtrij:true}, dat alleen wachtrij-URL's meldt; overige aanroepen alleen cron/supervisor. Waarom: geen geheim in de database en elk resultaat gelogd.
- Starterbeoordeling: alleen de inschrijvingsdatum van de huidige KVK-inschrijving telt (jonger dan 12 maanden op de ingangsdatum); een omzetting van eenmanszaak naar een nieuwe BV telt als starter, eerdere inschrijvingen tellen niet mee. Waarom: één toetsbare regel zonder voorgeschiedenisonderzoek.

- Koppelingscontrole Exact (testrelatie, dubbel exact_account_id, sterk afwijkende naam) via RPC exact_koppeling_controle in de ochtendrun van exact-concept-controle, die eerst exact-spiegel-sync stap accounts ververst (alleen GET). Waarom: verkeerde koppelingen vallen binnen een werkdag op zonder automatische correctie.
- Stilzwijgende verlenging: een einddatum op een contract blokkeert facturatie nooit; alleen contract_opzegging(id) (audit handmatig_beeindigd/opzegging_verwerk(en|t)/einddatum_opzegging_bevestigd of cyber lead opgezegd/gepauzeerd) blokkeert met soort 'opgezegd'. Waarom: besluit D1-aanvulling, wie niet opzegt wordt verlengd.
- Datumkolommen op leads/klant_contracten/policies/bav_aanmeldingen wijzigen alleen supervisor/admin/verzekering (2FA) of service_role (trigger guard_datums_alleen_intern); ingangsdatum via RPC lead_ingangsdatum_wijzigen. Waarom: klant kiest één keer bij aanmelding.
- Live-sitebezoeken alleen via RPC site_bezoek (vaste categorieen, throttle in de RPC); nooit IP, user agent, cookies of sessie-id opslaan. Waarom: anoniem live-overzicht zonder persoonsgegevens.
- Article images: leased queue, wake token or MFA supervisor, max 2 AI attempts then category fallback; never a global pause (AI refusal only sets admin notice); crashed jobs resume as fallback. Preserve custom/old assets; build verifies images; keep ArticleImage guard. Why: every article gets an image within minutes.
- Reviewverzoeken alleen via review-verzoeken (cron, schakelaar 'reviewverzoeken_actief', RPC review_kandidaten); afmelden alleen naar review_afmeldingen, nooit suppressed_emails. Waarom: één filter, transactionele mail blijft.
- Geen nabelmail meer (aanvraag-nabellen is no-op, cron uit); afhaak-herinnering stuurt pas na een verstuurde herinnering één interne melding; placeholder-testinvoer staat in _shared/testInvoer.ts; admin toont reden via afhaak_geen_herinnering_reden; dagelijkse samenvatting per afhaker via bouwAfgehaaktSamenvatting (_shared/nabellen.ts), testinvoer alleen als aantal. Validatiefouten alleen als stap+veldnaam via submit-public-form naar aanvraag_validatiefouten. KVK-invoer via _shared/kvkInvoer.ts. Waarom: afhakers krijgen een mail, geen belletje.
- Nieuwe klantmails alleen via verstuurKlantmail (_shared/klantmailSchakelaar.ts): leest klantmail_instellingen vers, verstuurt alleen bij actief en status <> wacht_op_akkoord_boy, anders logregel in klantmail_log; aanzetten alleen via RPC zet_klantmail_actief (admin, akkoord Boy gelogd); tekst wijzigen zet de mail weer uit. Waarom: niets naar klanten zonder akkoord Boy.
- D8 prolongatie: prolongatie-jaarpolis (cron 06:40/07:40 UTC, alleen 08 uur NL) via prolongatie_kandidaten, uniek in prolongatie_log. Waarom: elk contract een keer per verlengdatum.
- Financieel overzicht: Exact alleen GET via exact-finance-sync (cron 05:50 NL of supervisor/admin), cache in exact_*_cache met upsert op Exact-id; cijfers alleen via finance_overzicht/finance_aansluiting, 'nu open' alleen uit de laatste volledige run (finance_open_run). Waarom: een getal voor admin en agents, niets naar Exact.
- Netto groei op het dashboard alleen via tel_netto_groei (aantallen, bav_avb + cyber_clear); /tv gebruikt scherm_groei (klanten met een factureerbaar contract, begin + nieuw - gestopt = nu). Waarom: A6 een bron per scherm, geen bedragen of namen op /tv.
- Ad images: SQL insert into advertentie_beelden wakes advertentie-beeld (empty body, host allowlist, cover-crop JPG) into article-images/ad-images/ (public buckets blocked). Why: reusable for Ads.
- NPS (A22) loopt alleen via nps-verzoeken (cron, schakelaar facturatie_config.nps_actief) en publieke nps-antwoord -> RPC nps_antwoord_opslaan (lage score = één open crm_taak nps_laag_bellen); mijn_acties_vandaag is een wrapper rond mijn_acties_vandaag_basis. Why: no customer mail without the switch, no review-gating, existing today-list unchanged.

- /scherm en /tv: data alleen via scherm-data (SCHERM_TOKEN of apparaattoken, alleen sha-256 in scherm_apparaten; koppelen via scherm-koppel); machine_activiteit-triggers laten nooit de actie falen; fout = cache met X-Cache stale + verouderd_sinds; pagina herlaadt bij nieuwe build (src/lib/versieControle.ts). Waarom: intrekbare toegang, stilstand zichtbaar.
- Bewust vervallen eerste concepten behouden Exact-id met exact_invoice_vervallen_op; conceptControle sluit ze uit van controle, SQL van werktellers. Waarom: nooit verwijderd/verwerkt suggereren of opnieuw maken.
- Schermwerktuin (A8-correctie): poppetjes zijn het hoofdbeeld; plek per robotnaam in MachineScene POPPETJE_PLEK, afdelingslabel via AFDELING_TAG, machine-afdelingen als kleine chips; robot-afdeling in WERKPLEK (schermAnonimiseer.ts); workerruns via scherm_cron_schema() + _shared/cronVolgende.ts (UTC). Waarom: één bron voor robots, labels nooit over de poppetjes.

Regels over _shared-modules staan in supabase/functions/_shared/AGENTS.md, over de planner (inclusief opzeg-creditnota's en lidmaatschappen) in supabase/functions/factuur-planner/AGENTS.md en over certificaten in supabase/functions/generate-certificate/AGENTS.md. Regels over incasso-cyclus, hartslag, exact-adres-sync en analyze-dba staan in de AGENTS.md van die functiemap.
- Cyberingang eerder dan morgen alleen via cyber_terugwerkend_vroegst: Ellen bij cyber in de oorspronkelijke aanvraag, of een rij in cyber_ingang_uitzonderingen (per onderneming, reden verplicht, alleen service_role, alleen na besluit Boy). Waarom: standaardgrens blijft, uitzondering herleidbaar.
- Alleen cyber: eigen nummerreeks ZPCYB in cyber_nummers via cyber_nummer_toekennen; generate-certificate weigert BAV voor alleen-cyber (alleen_cyber), keuze via klant_dekking_actief. Mislukte incasso's via mislukte_incassos_kern (Exact-cache, bankgegevens zonder IBAN), daglijst incasso_daglijst_melden max 1/dag; facturen InvoiceText FACTUUR_BETAALTEKST, nooit op credits. Waarom: besluit Boy 9-11-2026.
- Openstaande betalingen: incasso_open_posten_sync (pg_cron 05:15 UTC) voegt Exact-storno's >14 dagen over vervaldatum toe (cyclus_actief=false) en sluit Exact-posten die niet meer openstaan; AFAS alleen via incasso_handmatig_betaald (notitie verplicht); contact via incasso_contact_gelegd; reviewselecties slaan onderneming_betaalachterstand over. Waarom: geen klantmail of opschorting zonder besluit, geen reviewverzoek bij achterstand.
